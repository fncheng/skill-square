大型前端项目中如何设计可维护的权限系统

从路由、组件、接口和数据四层说明权限模型，并给出 React 项目的实施边界。

核心结论

可维护的权限系统不应只依赖前端路由守卫。更稳妥的方式是将权限判断分为展示、导航、接口和数据范围四个层级，并让后端承担最终授权责任。

一、先定义统一的权限语义

建议使用“资源 + 动作”的稳定权限键，例如 prompt:read、prompt:update。角色只是权限集合，不应直接散落在页面判断中。

type Permission =
  | 'prompt:read'
  | 'prompt:create'
  | 'prompt:update'
  | 'prompt:delete';

二、前端负责体验，后端负责安全

前端路由守卫用于阻止无权限用户进入页面，组件级权限用于隐藏不可用操作。真正的安全边界必须位于后端接口，否则用户仍可以绕过界面直接发送请求。

三、集中管理权限判断

不要在组件中反复比较角色字符串。可以提供统一的 can(permission) 方法，并在路由配置与按钮组件中复用。
