React 并发渲染与状态更新实践

整理并发渲染、状态批处理与异步任务中的常见问题和可复用处理方式。

为什么需要区分更新优先级

在复杂交互中，输入、筛选和页面切换并不具有相同的紧急程度。将所有更新视为同步任务，会让耗时渲染阻塞用户正在进行的输入。

高频交互首先保证响应，非关键内容允许稍后完成，是并发渲染最直接的使用原则。

可以将输入框状态保持为紧急更新，将筛选结果计算放进非紧急更新。这样既保留了数据一致性，也减少了明显的输入延迟。

状态批处理的边界

React 会在常见事件和异步回调中合并多次状态更新。连续调用更新函数时，应优先使用函数式更新，避免读取到同一份旧状态。

  • 依赖前一个状态时使用函数式更新。
  • 不要将渲染后的 DOM 当作状态是否完成的唯一依据。
  • 确实需要同步读取布局时，再使用更严格的同步边界。

异步任务与会话所有权

详情页中的导出、批注加载和内容刷新可能同时发生。每个异步任务都应绑定当前资源标识，回调完成时再次确认页面仍属于同一资源。

如果用户已经切换到其他笔记，旧任务的结果不应覆盖新页面状态。可以使用请求取消、序列号或资源标识校验完成隔离。

实现检查清单

  • 关键按钮具备明确的 loading 和 disabled 状态。
  • 错误反馈不会清除用户尚未提交的内容。
  • 长标题和长标签不会挤压操作区域。
  • 页面滚动后仍能找到高频操作，但不遮挡正文标题。

补充说明

紧凑操作条只在原始操作区域离开视口后出现。用户回到页面顶部时，它会自动退出，不会形成两个同时可见的操作区域。

删除等低频危险操作收进更多菜单，避免与复制、批注等高频动作争夺视觉注意力。
