# Markdown 全屏编辑预览标题与段落高亮方案

## 1. 需求解释与可行性结论

已确认的交互定义：**以鼠标指针在左侧 Monaco 编辑区指向的源码行作为目标；编辑区滚动后，即使指针没有移动，也重新识别指针下的源码行，并在右侧预览中高亮对应内容。**鼠标移动到另一条源码行时同样更新；左侧不添加高亮。目标不取自 Monaco 的文本输入光标位置。

已确认的高亮范围：标题和普通文本段落。鼠标指向标题源码行时高亮右侧完整标题；指向普通文本时，无论该段落在源码中只有一行还是多行，都高亮右侧**整个段落**。代码块、Mermaid 图表、表格不显示高亮。列表、引用块、分隔线、空行和仅用于引用定义的源码行也先不参与，以免误把这些结构当成普通段落。

结论：**这个收窄方案比逐行高亮更可靠，也明显降低滚动期间的计算开销。**现有解析器已经产出顶层标题和段落 DOM，可直接切换元素样式，不需要推算预览的视觉行。不过，Markdown 连续文本行会合并成一个 `<p>`；鼠标在该段落的不同源码行间移动时，右侧保持同一段落高亮，这是预期行为。

视觉建议：右栏使用低饱和琥珀色 `#FEF3C7` 作为背景，辅以 `#F59E0B` 的细左边标识；标题和段落使用同一套提示样式，不改变文本颜色，不遮挡链接与引用入口。高亮离开编辑区、退出全屏、切换到窄屏单栏、关闭同步滚动或预览版本尚未追上源码时清除。

## 2. 当前代码与关键约束

- 五类 Markdown 编辑页复用 `apps/web/src/components/markdown/MarkdownEditorPanel.tsx`。全屏桌面端左右双栏可同步滚动；宽度不超过 960px 时改为编辑/预览标签页。
- `PromptMonacoEditor.tsx` 已将 Monaco 实例通过 `onEditorChange` 提供给父组件。Monaco 的 `getTargetAtClientPoint(clientX, clientY)` 可根据视口坐标命中源码位置；但指针不移动时，滚动不会自动产生新的 `pointermove` 事件，必须在滚动完成后的帧中再次命中测试。
- `use-markdown.ts` 在编辑预览模式提供顶层块 `blockId/startLine/endLine`；`MarkdownEditorPanel` 将其与预览 DOM 几何位置配对，用于滚动同步。顶层段落输出 `<p>`、标题输出 `<h1>` 至 `<h6>`，可作为高亮目标。当前块元数据没有类型标识，需要补充类型或在构建缓存时一次性读取 DOM 标签。
- 引用定义预处理会删除源码行，而当前块的起止行可能跨过被删除的行；行号落在该间隙时不能误亮段落。`MarkdownContent` 使用 `dangerouslySetInnerHTML` 更新文章，因此预览版本变化后须清除旧 DOM 引用并重新定位目标。
- 项目尚未通过本地浏览器验证现有滚动同步的运行手感；本方案涉及的性能判断是基于代码路径和复杂度的预估，最终必须在真实长文档中测量。

## 3. 候选方案

### A. 只高亮标题和普通段落元素（推荐）

沿用 `sourceBlocks`，鼠标行命中标题或普通段落时，仅给右侧对应的 `<h1>` 至 `<h6>` 或 `<p>` 切换高亮类；命中其他块时清除高亮。多行段落作为一个整体处理。

- 优点：符合已确认范围；无需测量每一视觉行，也不增加逐行 DOM 节点；在段落内部移动鼠标不会反复改样式。
- 缺点：极长段落会形成大面积背景，仍有重绘成本；列表和引用中的文本暂不高亮。
- 适用：当前共享编辑器与性能优先的交互。

### B. 对每条预览视觉行做几何定位

基于源码行在块内的比例估算右侧位置，再读取 `Range.getClientRects()` 选择最近的视觉行，用单独的覆盖层高亮。

- 优点：能把长段落缩小到一条视觉行。
- 缺点：与“多行文本高亮整个段落”的新定义不一致；滚动中几何读取、缓存失效和代码复杂度都更高，自动折行时仍是估计。
- 适用：将来明确改回视觉行级高亮时再评估。

### C. 解析时为每条源码行插入 DOM 标记

给每行正文添加 `data-source-line` 节点，直接按行号查找高亮目标。

- 优点：对普通段落可建立更明确的逐行关系。
- 缺点：每次预览重建都会增加与正文行数成正比的 DOM 节点与处理成本；当前需求已经按段落高亮，这项成本没有收益。
- 适用：未来逐行精度成为硬要求且文档规模受控的场景。

| 方案 | 复杂度 | 滚动时性能 | 预览重建成本 | 维护性 | 扩展性 | 实施成本 | 适用场景 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A 标题/段落类切换 | 低 | 块查找后常数级 DOM 操作 | 基本无新增 | 复用现有块映射 | 可按块类型增加支持 | 低 | 本次需求 |
| B 视觉行几何定位 | 中高 | 需按需测量与缓存 | 无全篇节点增加 | 几何失效逻辑较多 | 视觉行精度更高 | 中高 | 未来逐视觉行需求 |
| C 逐行 DOM 标记 | 高 | 行号查找快 | 每次输入增加 O(行数) 节点处理 | 解析/高亮/批注需联动 | 源码行精度更高 | 高 | 有明确逐行硬要求 |

## 4. 推荐方案的详细设计

### 4.1 指针行检测

只在桌面全屏双栏且鼠标等精细指针可用时工作。`pointermove` 只保存最新 `clientX/clientY` 和指针是否位于左侧编辑内容区。Monaco 滚动后，即使指针静止，也在下一次合并的 `requestAnimationFrame` 任务中调用 `getTargetAtClientPoint`，获取指针下新的源码行。若指针位于分隔条、滚动条、元数据侧板或编辑器外，清除高亮。

高亮更新安排在预览跟随滚动之后；若预览还在处理旧 `deferredValue`，先清除高亮，待渲染版本一致再恢复。鼠标在同一多行段落内部跨行时，目标段落不变，不触发重复 DOM 写入。

### 4.2 只匹配标题与普通段落

为 `sourceBlocks` 增加轻量的 `kind`（至少区分 `heading`、`paragraph` 与 `other`），或在一次性构建几何缓存时记录顶层元素标签。优先用显式块类型，避免滚动时重复检查 DOM。缓存同时保留 `blockId/startLine/endLine` 与预览元素引用；按源码行二分查找，找到非标题/普通段落块时直接清除高亮。列表项虽然是文本，但当前顶层解析结果把整个列表作为一个块，因此初版不纳入。

注意当前引用定义会在解析前被过滤：一个段落的 `startLine/endLine` 可能跨过被过滤的原始行。仅检查起止行不足以确认命中的源码行确实可见。解析阶段应提供被过滤行的轻量集合，或为可高亮块提供实际参与渲染的源码行索引；命中这些间隙时不高亮。空白行同样不高亮。预览重建后旧元素引用失效，要重建缓存并重新确认鼠标下的目标。

### 4.3 高亮渲染方式

只保留当前高亮的一个顶层元素引用。目标改变时，移除旧元素的 CSS 类，再给新元素添加类；预览内容替换时先清除引用。高亮样式限制在 `.editor-preview-content` 的标题和普通段落，不修改正文文本节点、不增加逐行节点，也不通过 React `setState` 驱动每个滚动帧。使用背景与 `box-shadow` 等不改变盒子尺寸的属性，避免排版和滚动位置变化；不要给大段落添加持续的背景色动画。

代码、图表、表格、列表、引用块和没有独立渲染内容的源码行**不回退为整块高亮**。这一点与旧方案不同，避免把不支持的内容误显示为已精确对应。

### 4.4 性能边界与验证指标

新范围移除了 `Range.getClientRects()`、视觉行矩形缓存和覆盖层；主要新增开销是 Monaco 命中测试与两个 DOM 元素的 CSS 类切换。仍须控制以下边界：

1. `pointermove`/滚动事件只保存坐标并调度任务；每帧最多进行一次 Monaco 命中测试和一次块查找，不在事件回调中更新 React 状态或全篇查询 DOM。
2. 块索引沿用滚动同步的重建时机，滚动期间用行号二分查找。若目标 `blockId` 没变，不改 DOM 类；鼠标在同一段落内移动不会带来新绘制。
3. 极长段落虽然没有几何测量，整块背景仍可能增加浏览器绘制面积。用极长单段落专项测试；若出现明显卡顿，可仅保留琥珀色左边标识或改为可见区域提示，不应在运行时增加逐行 DOM。
4. 避免对高亮背景使用持续动画；避免高亮触发 `scrollTop` 写入或破坏原有滚动同步反馈抑制。预览版本变化时清理旧节点，不保留失效引用。
5. 用相同内容对比功能开/关两种状态，在 1 千、5 千、1 万行且混合长段落、代码、表格和 Mermaid 的文档上测量滚轮期间主线程耗时、长任务、帧率、输入延迟与内存。建议新增高亮处理的 P95 预算不超过约 2 ms/帧；这只是验收目标，必须用浏览器实际测量。

## 5. 实施范围与验收用例

预计修改 `MarkdownEditorPanel.tsx`、`use-markdown.ts` 的块类型/过滤行元数据，以及 `main.css` 的高亮样式。现有 `PromptMonacoEditor.tsx` 已提供 Monaco 实例，原则上无需更改五类 Editor view、保存请求、后端 API、路由或数据库。

验收场景：鼠标静止时滚动左栏、快速反向滚动、鼠标跨源码行和跨段落、标题、单行段落、多行段落、自动换行、极长单段落、被过滤的引用定义与空行；确认代码块、Mermaid、表格、列表和引用块不显示高亮。再检查右栏自行滚动、分栏调宽、预览延迟更新、进入/退出全屏、关闭同步及窄屏标签页。高亮不得影响链接、引用浮层、代码复制、文本选择和批注，不得产生滚动跳跃。浏览器性能记录应与现有滚动同步基线分开报告。仓库规则禁止未经同意运行构建或编译命令。

## 6. 推荐结论

推荐 **A：仅高亮右侧标题或完整普通段落，其他块不高亮**。这与用户确认的范围一致，直接利用现有块映射，滚动时只需要一次源码行命中、一次块查找和最多两个元素的类切换。相较旧方案，取消逐视觉行几何测量及复杂块降级，定位含义更清晰，性能风险更低。主要剩余风险是极长段落的背景绘制，以及引用定义过滤造成的行号间隙；需在实施时处理并通过浏览器验证。
