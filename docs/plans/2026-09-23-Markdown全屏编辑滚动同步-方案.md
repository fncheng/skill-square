# Markdown 全屏编辑双栏滚动同步方案

## 1. 目标与现状

目标是在桌面端全屏双栏工作区中，无论用户滚动左侧 Markdown 源码还是右侧实时预览，另一栏都跟随到**对应的内容位置**。这里的“同步”指语义位置大致一致，不要求两个滚动条具有相同百分比或像素值。普通单栏编辑/预览切换和宽度不超过 960px 时的编辑/预览标签页无需双栏同步。

当前代码链路：

- 五类编辑页共用 `apps/web/src/components/markdown/MarkdownEditorPanel.tsx`，因此同步逻辑只应在这个共享组件及其编辑器、预览适配层接入。无需逐页更改保存或 API 逻辑。
- 左侧 `PromptMonacoEditor` 使用 `@monaco-editor/react` 包装 Monaco。Monaco 自行管理滚动；目前组件没有向父组件暴露编辑器实例。
- 右侧实际纵向滚动容器是 `.editor-preview-scroll`；`MarkdownPreview` 通过 `useMarkdown` → `MarkdownContent` 渲染，`MarkdownEditorPanel` 用 `useDeferredValue` 延迟预览更新。
- 现有解析器按块输出 HTML，但没有记录原始行号。`extractReferenceDefinitions` 会先移除引用定义行；Mermaid 在 `MarkdownContent` 中异步替换占位内容，预览高度会在初次渲染后变化。
- 全屏桌面布局的两列可拖动调宽；窄屏改为单列标签页。同步不得重建 Monaco 或接管元数据侧板的滚动。

约束：沿用现有 React、Monaco 和 Markdown 渲染链，不新增 UI 框架或第二套 Markdown 解析器。本轮只交付方案文档，不修改功能代码。

## 2. 交互定义

1. 桌面端进入全屏双栏时，默认开启双向同步。左栏滚动带动右栏，右栏滚动也带动左栏；拖动滚动条、鼠标滚轮、触控板和键盘滚动遵循同一规则。
2. 全屏工具栏提供一个“同步滚动”切换按钮，带明确按下状态和无障碍名称。关闭后两栏恢复独立滚动；此设置初期只在当前编辑会话内有效。切换开启时，以最后主动滚动的一栏为基准对齐一次。
3. 仅响应**实际纵向滚动**。输入文字或移动光标本身不强制跳动预览；若 Monaco 为显示光标而实际滚动，则可触发同步。代码块或表格内部的横向滚动不得移动另一栏。
4. 同步目标是当前视口上部约 25% 处所在的内容块。文档最顶部和最底部要准确对齐。用户反向滚动另一栏时，立即以新的主动栏为基准，不出现来回抖动。
5. 预览重排时，保持主动栏的位置，待新渲染或 Mermaid 高度稳定后重新定位跟随栏；不因右栏高度变化强行滚动正在操作的左栏。元数据侧板滚动与双栏同步无关。

## 3. 候选方案

### A. 按总滚动比例映射

计算 `scrollTop / (scrollHeight - clientHeight)`，将比例写入另一栏。Monaco 侧通过编辑器 API 读取和设置滚动位置，预览侧使用 DOM `scrollTop`。

- 优点：实现简单，不需要改解析器；对于两栏高度近似的纯文本，效果尚可。
- 缺点：Markdown 标题、代码块、表格、引用和 Mermaid 的渲染高度与源码高度差异很大；开头插入内容会导致整篇映射漂移。它只能保证滚动条比例一致，不能保证看到对应段落。
- 适用：短文档、临时过渡或语义锚点缺失时的降级路径。

### B. 标题锚点加区间比例

在源码中找标题行，与预览 DOM 中同序号标题配对。滚动位置落在两个标题之间时，按该区间内的相对比例插值。没有标题时回退到 A。

- 优点：比总比例更贴合常见笔记结构；不需要给每个段落添加标记。
- 缺点：长章节、无标题文档仍有明显错位。直接用正则扫描 `#` 容易误判围栏代码中的伪标题；现有 `headings` 没有源行号，需改造解析结果或另写有状态扫描器。
- 适用：内容以短章节为主、接受章节内偏差的产品。

### C. 源码块与渲染块对应，区间插值并按比例降级（推荐）

在现有 Markdown 解析过程中，为顶层段落、标题、列表、引用、代码块、表格和分隔线记录原始源码起止行，并给对应预览块一个稳定的数字标识。用 Monaco 的行布局位置与预览块的 DOM 位置建立锚点；视口落在块内时，在该块的两端之间插值。缺少有效块或文档为空时，回退到 A。

- 优点：滚动目标与具体内容对应，对无标题文档和长章节也有效；仍复用正式渲染结果和 Monaco 实例；改动集中在共享组件与解析层。
- 缺点：解析器需维护原始行号映射；引用定义行被移除、递归引用块、折行和异步 Mermaid 需要专门处理。实现和验收成本最高。
- 适用：当前五类共享 Markdown 编辑页，希望长期保持可用的双向同步体验。

| 方案 | 复杂度 | 性能 | 维护性 | 扩展性 | 实施成本 | 适用场景 |
| --- | --- | --- | --- | --- | --- | --- |
| A 总比例 | 低 | 每次滚动 O(1) | 简单，但错位属于固有问题 | 与内容结构无关 | 低 | 短文档、降级 |
| B 标题锚点 | 中 | 锚点缓存后滚动查找可为 O(log n) | 需维护标题行与 DOM 配对 | 适合标题密集文档 | 中 | 分节明确的笔记 |
| C 块锚点加降级 | 中高 | 锚点缓存后滚动查找可为 O(log n)，重排时更新几何数据 | 解析器与预览共享一套块元数据 | 覆盖无标题及复杂块 | 中高 | 当前正式编辑工作区 |

## 4. 推荐方案的技术设计

### 4.1 生成稳定的内容映射

扩展 `useMarkdown` 的解析结果，提供可选的源位置映射；只有编辑预览请求该映射，详情页原有 HTML 行为保持不变。每个顶层块记录 `{ blockId, startLine, endLine }`，渲染 DOM 写入对应 `data-md-block-id`。`blockId` 使用当次解析内的顺序号，不依赖标题文本，避免重复标题和标题编辑造成匹配错误。

`extractReferenceDefinitions` 在过滤定义行时保留“解析行号 → 原始行号”表，不能以过滤后的行号直接定位 Monaco。递归引用块要把子块位置转换回原始行号；第一阶段可以仅使用顶层引用块作为锚点，不必映射内部每一行。空白、被剥离的引用定义及不能稳定对应的片段，通过最近块或总比例降级。源码和映射必须来自同一份 `deferredValue`，防止新文本行号与旧预览 DOM 混配。

### 4.2 获取两侧滚动位置

在 `PromptMonacoEditor` 增加可选的 `onMount`/实例回调，向 `MarkdownEditorPanel` 提供 `IStandaloneCodeEditor`，并在卸载时清理引用与订阅。Monaco 使用 `onDidScrollChange`、`getScrollTop`、`setScrollTop`、`getTopForLineNumber`、`getBottomForLineNumber`；预览使用 `.editor-preview-scroll` 的 `scroll` 事件及 `scrollTop`。这些 API 在仓库当前安装的 Monaco 类型定义中存在；`@monaco-editor/react` 支持 `onMount` 获取实例。

块锚点的源码位置由 Monaco 行高与折行后的实际布局计算，预览位置由块 DOM 相对滚动容器的位置计算。滚动时取当前视口上部 25% 的文档坐标，找其所在或相邻的块，在对应块的两个端点之间插值，再减去目标视口同样的 25% 偏移。目标值限制在合法滚动范围内；文档起点、终点单独精确对齐。不要逐行调用 DOM 查询或重新解析全文，滚动帧只读取缓存锚点并做二分查找。

### 4.3 双向驱动与布局变化

两个方向使用同一映射函数，但每次只有一个主动栏。通过 `requestAnimationFrame` 合并连续滚动事件；写入跟随栏的目标位置后，标记本次程序滚动及目标值，在回调中忽略其对应事件，避免反馈循环。用户在另一栏开始滚动时立即切换主动栏。位置差不足约 2px 时不写入，减少抖动。

全屏状态、分栏宽度变化、窗口尺寸变化、Markdown 渲染提交和 Mermaid 异步完成都会使锚点几何位置失效。使用 Monaco 的 `onDidContentSizeChange` 监测编辑区布局变化，并用 `ResizeObserver` 观察预览内容和两栏容器尺寸，在下一帧重建几何缓存；预览仍是延迟渲染时暂停语义映射，等预览版本与映射一致后再以主动栏位置补齐一次，不用旧锚点推动新源码。宽度不超过 960px 时两栏互斥显示，停止监听与同步；恢复桌面双栏时重算锚点。

### 4.4 接入范围

- `apps/web/src/components/prompt/PromptMonacoEditor.tsx`：可选暴露 Monaco 实例，保持原使用处不受影响。
- `apps/web/src/hooks/use-markdown.ts`：可选块级源位置与 DOM 标识；处理引用定义过滤后的行号映射。
- `apps/web/src/components/markdown/MarkdownEditorPanel.tsx`：管理同步开关、主动栏、滚动订阅、缓存、动画帧和清理；预览容器提供 ref。
- `apps/web/src/assets/main.css`：全屏工具栏同步按钮在桌面和窄屏的显示规则；如需要，为预览滚动设置 `overscroll-behavior`。
- 不需要修改五类 Editor view、保存请求、后端 API、数据库或路由。

## 5. 风险、验收与实施顺序

主要风险是复杂块的高度变化：Mermaid 先占位再出现 SVG，长代码、表格和折行也会造成两侧高度差。块锚点允许块内一定偏差，但应保证当前段落或代码块大致对应；异步重排不能把主动栏拉走。另一个风险是长文档每次输入都重建映射，因此应在预览完成后批量测量、滚动期间复用缓存，并在销毁时清理 `requestAnimationFrame`、Monaco 订阅和 `ResizeObserver`。

建议实施顺序：

1. 先给解析器补源行号映射，验证标题、连续段落、列表、表格、围栏代码、引用块和被过滤的引用定义。
2. 在共享面板接入 Monaco 与预览容器，完成单向映射，再补反向驱动和反馈抑制。
3. 接入延迟渲染、窗口/分栏变宽、Mermaid 高度变化时的锚点更新；加入同步开关和无标题文档降级。
4. 在已有开发页面做人工交互验收：短文档、长文档、无标题文档、插入/删除段落、长代码块、表格、Mermaid、引用定义、拖动分栏、快速反向滚动、关闭同步、退出/重进全屏、保存后继续编辑。特别检查普通单栏与窄屏标签页不受影响。

验收标准：预览版本就绪后，主动滚动任一栏，另一栏在随后一个动画帧的稳定状态落在相同或相邻的顶层内容块；没有持续震荡、明显反向跳动或 Monaco 实例重建。无法产生块映射时可按总比例降级，但应记录可复现的文档样例，确认降级范围。静态检查和浏览器交互检查分别报告；仓库规则禁止未经许可运行构建或编译命令。

## 6. 结论

推荐 **C：块级语义锚点同步，比例映射兜底**。现有双栏滚动容器彼此独立，且 Markdown 的视觉高度与源码高度差异显著；块级映射是满足“滚动到对应内容”这一目标最可靠、且能在五类页面复用的方案。同步默认开启，并允许用户在全屏工具栏临时关闭。
