# SKILL center 功能与交互方案

> 状态：设计提案，尚未实施。本文所有新增模型、接口、限制和交互规则均为建议，不代表现有系统已具备这些能力。
> 关联：[项目文档入口](../README.md) · [Prompt 资源库](../features/prompt-library/README.md) · [访问控制](../features/access-control/README.md) · [HTML 原型](../../prototype/skill-center.html)

## 1. 推荐结论

新增独立的 **SKILL center** 左侧导航入口，首期建设仅管理员可见的个人 SKILL 仓库。以“上传完整版本、跨设备下载指定版本”为核心路径，支持单个 `SKILL.md` 和完整目录 ZIP。每次内容更新创建不可变版本快照，详情提供文件浏览、历史记录和任意两个版本的对比。

不要将 SKILL 塞入现有 Prompt 正文，也不要将 ZIP 更新视为与旧文件合并。SKILL 是包含说明文档与辅助文件的可下载资源；每个 ZIP 都代表一个完整版本，旧版本存在而新包缺少的文件，在新版本中即为删除。

首期不做自动同步、客户端安装、多用户空间和公开分享。后续分享应明确授权某个版本，而非直接沿用现有公开 GET 规则。原型展示的“仅自己可见”对应当前单管理员模型，不意味着已经存在用户所有权体系。

## 3. 目标、范围与成功路径

### 首期范围

- 资源列表：名称搜索、单文件/目录包筛选、更新时间排序，展示名称、简介、格式、当前版本、文件数、更新时间。
- 新增：上传 `SKILL.md` 或 ZIP；也可手动填写单文件内容创建 SKILL。
- 更新：从已有详情“上传新版本”进入，目标资源固定，填写变更说明，确认后追加版本。
- 详情：当前版本与指定历史版本的文件列表、文本内容、元信息、下载。
- 历史：倒序记录版本号、生成时间、来源、变更说明、文件变化摘要；浏览与下载历史版本。
- 对比：选择任意两个版本，先看新增/修改/删除文件清单，再看文本差异；二进制只展示状态、大小和摘要变化。
- 删除：确认后删除整个 SKILL 及其全部历史。首期不提供单独删除某个历史版本。

### 延后范围

分享链接、公开广场、其他用户上传、评分、收藏、自动监测本地目录、双向同步、冲突合并、CLI、直接写入本地安装路径均不纳入首期。回滚可作为后续增强：如需加入，应通过旧快照创建新版本，不能改写历史。

### 成功路径

1. 设备 A 登录同一站点，上传 ZIP，确认识别结果后创建 v1。
2. 在本地修改目录，重新打包；从该 SKILL 详情上传 v2，并填写变更说明。
3. 查看 v1 → v2 的目录变化与 `SKILL.md` 文本差异。
4. 设备 B 登录同一站点，下载明确标注版本号的完整包；由用户自行解压、备份并替换本地目录。
5. 需要旧版本时，从历史记录下载 v1，无须覆盖网站当前版本。

网站不声称知道设备 B 是否已安装、是否为最新，下载成功也不等于本地同步完成。

## 4. 页面结构与体验设计

### 4.1 管理列表

沿用顶栏与侧栏，SKILL center 作为左侧一级入口。主标题下显示资源数量和用途说明；右侧“上传 SKILL”为主按钮，“新增”为次按钮。表格适合比较版本与格式，比重复的大卡片更容易扫描。

列表每行提供名称入口、下载和删除。下载点击时捕获明确版本，避免下载过程中“最新版本”变化造成文件和标题不一致。无数据时提供上传入口；无搜索结果时提供清除筛选；加载与失败保留导航和重试能力。

### 4.2 上传与新增

上传弹窗分为“选择文件 → 确认并保存”。选择文件后先校验并解析，再展示资源名称、说明、识别出的入口和文件数量。包校验失败不能保存，错误应指出文件路径或原因。

- 单文件：文件名要求为 `SKILL.md`，大小写规则建议严格匹配；验证 UTF-8 与入口 frontmatter 的 `name`、`description`。错误保留文件选择和已填写内容。
- ZIP：允许根目录直接放 `SKILL.md`，或仅有一个包裹目录且其下放 `SKILL.md`。只剥离这一层包裹目录；不递归寻找任意深度入口，不将多个 SKILL 自动拆包。
- 新增名称、说明可从入口 frontmatter 读取；展示名称允许独立于入口中的标识，名称并不承担资源 ID 的职责。不自动重写原始 `SKILL.md`。
- 手动新增：填写展示名称、简介与入口内容，生成单文件 v1；正式页面使用项目已有 Monaco。HTML 原型使用基础输入控件模拟，不改变正式编辑器约定。
- 同名资源：不自动覆盖。提示用户前往已有 SKILL 上传新版本，或明确选择另建资源。更新依据资源 ID，而非 ZIP 文件名或 frontmatter 名称。
- “上传新版本”固定资源目标，来源格式可改变，但从目录包切换为单文件时明确提示其他文件将从新版本消失，必须确认。
- v1 使用“首次上传”说明；后续版本建议要求填写简短变更说明。相同规范化文件内容及元信息不新增版本；仅修改 ZIP 时间戳或压缩方式也视为相同。下载历史原包的字节不因此被替换。
- 保存时禁用重复提交，后台失败保留草稿并允许重试。取消和关闭不产生版本；文件尚在解析时更换文件或关闭，旧任务结果不得覆盖当前选择。

### 4.3 详情与文件浏览

顶部为名称、简介、格式、版本与更新时间；操作为“下载此版本”“上传新版本”，删除作为弱化的危险操作。选择历史版本后显示明确的历史版本状态及“回到当前版本”。上传始终基于当前最新版本，不以正在浏览的旧版本作为覆盖目标。

“文件 / 版本历史 / 版本对比”三级工作页签。文件页左侧为规范化相对路径，右侧为只读文本和元信息。`SKILL.md` 为默认选中入口。脚本只作为文本展示，绝不执行；HTML 不直接运行；二进制和过大文本显示不可预览原因。浏览与下载分开，避免点击文件名误触下载。

### 4.4 历史与对比

历史列表保留稳定版本号，不把更新时间当版本标识。每行提供查看、与前一版比较、下载。v1 没有前一版，比较按钮禁用。

对比默认“上一版 → 当前版”，允许任意选择不同的两版并交换方向。相同版本只显示“所选版本相同”，不伪造差异。目录对比按相对路径：新增、删除、修改、未变；文件重命名首期按删除+新增展示。整包哈希不同不能直接推出所有文件都有修改。

- Markdown：原始文本逐行对比，同时覆盖 frontmatter，不能只对比渲染后正文。
- ZIP：先按路径和文件内容摘要对比清单；选中文本文件后逐行对比。新增或删除一侧为空，不能显示旧版的其他内容。
- 二进制：只显示大小与摘要状态，不做文本解码。由指定版本下载完整包，首期不提供单个附件独立下载。
- 容量或耗时超限时，清单仍可查看，文本差异显示“无法在线对比，请下载查看”。
- 桌面左右对照并保留行号与增删标识；移动端改为纵向旧版/新版，不依赖颜色单独表达状态。

### 4.5 删除、反馈与可访问性

删除弹窗展示名称与历史版本数量，明确说明会删除所有版本并且无法从界面恢复；确认后返回列表并提示结果，失败保留原记录。正式删除遵守既有会话与确认流程。

交互提供 hover、focus、禁用、处理中反馈；弹窗有标题、关闭按钮、Esc、焦点约束和关闭后焦点恢复。危险按钮红色，普通按钮不争夺主操作。长文件路径允许换行，代码区内部滚动，不推动整个页面横向滚动。

## 5. 版本、文件与下载规则

### 推荐概念模型（未定稿接口或数据库契约）

| 对象 | 建议职责 |
| --- | --- |
| Skill | 稳定 ID、当前版本指针、创建与更新时间；列表名称和简介取当前快照，避免标题与正文跨版本错配 |
| SkillVersion | 资源 ID、连续版本号、展示名称/简介、上传来源、原始文件名、变更说明、格式、入口、规范化清单摘要、原包摘要、生成时间；快照不可变 |
| SkillFile | 所属版本、规范化相对路径、文件类型、字节数、内容摘要、可预览状态及有界文本；包含完整清单，不只保存变动项 |
| SkillArtifact | 指定版本的原始上传二进制；手动创建时为生成的 UTF-8 `SKILL.md` |

建议每个已发布版本都有完整可恢复的文件集。文本用于浏览和对比，下载以原始文件为准，避免解码再编码改变换行、编码或 ZIP 属性。

单文件下载为 `SKILL.md`，浏览器下载说明显示资源名和版本；目录包建议下载为 `<name>-vN.zip`，内容保留上传时的原始结构。包根路径会在详情说明，不把网站数据库 ID 或历史记录写进下载文件。服务端返回明确 MIME 与附件响应头，文件名去除控制字符及危险路径。

跨设备并发上传建议携带“打开上传窗口时的当前版本 ID”。提交时资源已变化则拒绝并提示重新查看差异，不能静默覆盖。版本号分配和当前指针更新必须在同一事务中，并设资源+版本号唯一约束；同一次保存通过幂等标识避免重试生成重复版本。

## 6. 技术路径与取舍

### 资源建模候选

| 方案 | 优点 | 缺点及适用场景 | 结论 |
| --- | --- | --- | --- |
| 扩展 Prompt 正文并内嵌 ZIP | 可沿用部分界面 | 单文本与目录文件集语义不同，下载、二进制和文件差异都需特例；仅纯文本收藏可用 | 不推荐 |
| 独立 SKILL 模块，完整版本快照 | 权限、目录清单、版本下载有明确边界；不影响现有 Prompt | 需要新增上传、快照及文件对比能力；适合本需求 | 推荐 |

### 原包存储候选

| 路径 | 优点 | 代价与适用条件 |
| --- | --- | --- |
| PostgreSQL 二进制列 | 现有仅数据库持久卷即可部署；元信息与原包可在事务内一致保存、统一备份 | 历史包会增加数据库、WAL 和备份体积；适合个人、小体积、有上限的首期 |
| 独立本地附件卷 | 下载不必读取数据库大字段；单机可用 | 需新增挂载、路径隔离、文件与数据库跨存储一致性、配套备份；适合文件量更大的单机部署 |
| 对象存储 | 大量文件、独立生命周期管理较合适 | 引入新的部署依赖、凭据和孤儿对象清理；当前没有已确认的基础设施 |

**首期条件性推荐 PostgreSQL 保存有界原包与版本清单**，减少个人部署和恢复的组件数量；列表查询不能带出原包。若已有可用对象存储或预计大量大型历史包，应在实施前切换为存储适配接口+对象存储。该选择未经容量、吞吐或备份时间测量，不承诺性能。最大代价是数据库持续增长，必须把容量预期作为实施前确认项。

正式实现保持 React/NestJS/Prisma：新增独立 views、api、types 和后端业务模块，复用 `PageHead`、Button、Toast、确认弹窗、Monaco 和会话保护。建议能力包括资源查询、候选包校验、新建、追加版本、版本清单、版本文件、版本比较、版本下载、整项删除；准确路径、DTO、响应类型在实施阶段确认并补 Swagger 与 API 文档。本轮不创建接口或迁移文件。

## 7. 文件包校验与权限边界

以下是实施建议，不是已经生效的产品限制。

- 初始建议上限：上传 10 MiB、解压后总量 50 MiB、500 个文件、单个在线文本预览/对比 1 MiB。还需限制解压比、嵌套深度、解析时间与单次内存。数值按真实样本验证后确定；前端提示与服务端配置应一致。
- 服务端流式计数并校验真实文件内容；扩展名和浏览器 MIME 不能作为唯一依据。
- 拒绝绝对路径、`..`、Windows 盘符、符号链接、加密包、重复规范路径和大小写冲突路径；避免在不同设备解压产生歧义。隐藏文件不静默剔除，系统垃圾文件是否忽略需明确告知；建议只忽略明确的 `__MACOSX` 与 `.DS_Store`，原始包仍原样保留。
- 单根目录和唯一入口规则解析失败时提示用户重新打包；不执行包内文件、不递归解压包内压缩文件、不在网站尝试安装。
- 私有列表、历史、正文、差异、下载、候选上传都验证管理员会话；正文与原包不能挂在公开静态目录。私有响应不进入共享缓存。
- ZIP 与 Markdown 名称、说明、文件路径以文本渲染；Markdown 复用现有安全策略，不能让上传文件注入页面或主应用上下文。
- 新建/追加快照失败不应留下可见的半版本；删除资源与数据库中原包、文件快照在事务内一致删除。已有备份的保留和恢复与应用内删除分开说明。

## 8. 后续分享设计

分享应作为单独阶段实现。建议从私有详情显式创建“固定版本”的只读链接，可撤销；外部页面仅展示该版本的说明、文件清单与下载，不泄漏历史或私有列表。是否支持有效期、密码和公开索引需另行确认。对外分享先增加资源级授权校验，再考虑公开发现，不能仅给现有私有接口加一个链接。

若以后真正引入其他用户上传，需要用户身份、资源归属与空间权限，当前固定 `admin` 不能直接承担多人所有权。此变化会改变数据模型与鉴权方案，应另行设计。

## 9. 原型预览与能力边界

打开 [skill-center.html](../../prototype/skill-center.html)，可直接双击文件使用，不依赖服务器、CDN、外部字体或构建。原型只在内存中保存，刷新恢复示例；不会上传到真实站点。

可体验：列表搜索/筛选、单文件与目录包详情、任意历史查看、双版本与多文件比较、实际示例文件下载、新增单文件、实际选择 `SKILL.md`、上传新版本、删除确认、空状态与错误反馈。使用上传窗口的“载入示例目录包”体验 ZIP 完整流程，重复载入更新样例可形成新版本。

原型对真实 ZIP 仅识别文件类型，不解析其目录，也不允许将未解析包保存为已校验资源；会提示使用示例包体验目录流程。示例下载在浏览器生成真实、无压缩 ZIP，包含示例文本文件。真实 Markdown 只校验入口名称、大小和非空 UTF-8，不替代正式 frontmatter 校验。对比为有界示例逐行算法；脚本及下载均为原型功能，未连接业务后端。二进制对比与大文件降级规则在本方案中定义，原型用状态表达而非生产解析器。

其他侧栏入口仅展示位置，不跳转业务系统。分享入口标记后续开放。HTML 中的编辑控件仅用于原型演示，正式实现继续使用 Monaco。
