# 编辑页加载期间输入可能被详情覆盖

来源：会话 `01a1dfea-7493-7ba2-9569-9f5587ba3f06` 的高优先级审查问题。状态 `fixed` 表示代码修复已提交，不代表所有浏览器与真实接口场景均已验收。

## 问题现象和影响

已有资源编辑页在详情返回前显示可输入的空表单；后到的详情可能覆盖用户输入。辅助列表请求失败也可能阻断详情加载。影响基于代码路径推断，未运行复现。

## 预期行为与复现步骤

1. 延迟已有资源的详情请求，尝试在响应前输入或保存。
2. 分别使分类或列表请求失败、使详情请求失败。
3. 详情加载前不能编辑或保存；辅助请求失败不阻断详情；详情失败时可重试，不能用空表单覆盖资源。

## 原因与实际修改

原初始化先等待辅助数据再加载详情，并将详情直接写入表单，缺少加载和失败状态。`7d9e3a9` 将辅助数据与详情独立请求，详情加载或失败时隐藏编辑表单，失败提供重试，并忽略已失效请求的返回。影响 Prompt、解决方案、学习笔记、杂谈、模型回答和 UI 原型编辑页。

## 验证结果

- 已进行代码检查，修改文件的语法解析及 `git diff --check` 通过。
- 本地 Chrome：打开无效 Prompt 编辑地址，真实详情请求失败后显示无法编辑和重试按钮，没有显示表单；点击重试后仍显示失败。
- 未模拟延迟详情或辅助请求失败，也未验证其他资源的失败与重试；未运行构建或编译。

- [ ] 模拟辅助请求失败，检查详情仍可加载。
- [ ] 模拟详情失败及重试，检查不能提交空表单。
