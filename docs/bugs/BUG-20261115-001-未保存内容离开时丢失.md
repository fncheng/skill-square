# 未保存内容离开编辑页或关闭 SKILL 弹窗时丢失

来源：会话 `01a1dfea-7493-7ba2-9569-9f5587ba3f06` 的高优先级审查问题。状态 `fixed` 表示代码修复已提交，不代表所有浏览器与真实接口场景均已验收。

## 问题现象和影响

编辑页返回、浏览器导航或关闭 SKILL 手动编辑弹窗时，尚未保存的内容可能丢失。该影响来自代码路径推断，原审查未运行复现。

## 预期行为与复现步骤

1. 在资源编辑页修改正文或元数据，尝试页内返回、浏览器返回、刷新或关闭页面。
2. 修改 SKILL 手动编辑弹窗后，尝试关闭、取消或按 Escape。
3. 未保存时应允许继续编辑或放弃修改；没有修改或成功保存后不应提示。全屏切换不应误报。

## 原因与实际修改

原编辑页没有导航或 `beforeunload` 拦截，SKILL 手动编辑弹窗的关闭入口直接关闭。新增 `use-unsaved-changes.ts`，以表单快照判断变化并接入路由及浏览器提示；路由入口改用 `createBrowserRouter`，保存和加载完成后更新基线。SKILL 手动弹窗的关闭入口也进行确认。

同一路径的查询参数或 hash 变化也纳入离开判断，避免切换 SKILL 工具适配时重载详情并丢失弹窗内容。SKILL 弹窗关闭确认复用项目确认组件；Prompt 保存后以实际提交的规范化字段更新显示与基线，并保留请求期间发生的后续输入。

涉及 `apps/web/src/main.tsx`、`apps/web/src/hooks/use-unsaved-changes.ts`、六类资源编辑页和 `apps/web/src/views/SkillCenter.tsx`。

## 验证结果

- 已进行代码检查，修改文件的语法解析及 `git diff --check` 通过。
- 本地 Chrome：新建 Prompt 修改名称后，页内返回和刷新均提示；取消后内容保留，进入及退出全屏没有误报，恢复名称后可直接离开。
- 本地 Chrome：SKILL 手动新增修改名称后，取消和 Escape 均提示；选择继续编辑后内容保留。
- PR 复核后的定向检查覆盖路径、查询参数、hash 变化，以及 Prompt 字段规范化和后续输入保留；本次修改后的浏览器交互尚未验证。
- 未验证正文修改、浏览器返回、保存成功后的基线、其他资源及所有 SKILL 关闭入口；未运行构建或编译。
