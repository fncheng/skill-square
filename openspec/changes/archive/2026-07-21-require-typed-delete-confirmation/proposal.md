## Why

当前所有删除操作只需点击一次危险按钮即可确认，容易因误触或目标识别错误造成不可恢复的数据丢失。为所有用户可见的删除入口增加输入确认，可以让用户在执行删除前再次核对具体目标，并明确级联删除等实际影响。

## What Changes

- 所有 Prompt、解决方案、学习笔记、UI 原型、分类和标签删除操作，均要求用户输入对应资源的名称或标题后才能确认删除。
- 删除批注时要求输入固定确认文本 `删除批注`，避免让用户输入可能很长且包含 Markdown、代码或换行的批注原文。
- 删除确认弹窗展示待输入文本，并在输入内容匹配前禁用确认删除按钮；取消或关闭弹窗后清空本次输入。
- 普通确认操作继续使用无需输入文本的确认流程，例如 Prompt 版本回滚不受影响。
- 删除文案明确说明实际影响，包括 Prompt 历史版本、解决方案和学习笔记的批注、分类引用以及标签关联。
- 输入确认仅用于前端防误操作，不改变现有 DELETE API 契约。

## Capabilities

### New Capabilities

- `typed-delete-confirmation`: 定义所有用户可见删除操作的输入确认、文本匹配、交互状态和影响提示要求。

### Modified Capabilities

无。

## Impact

- 前端全局确认状态、确认 hook 与确认弹窗组件需要支持可选的输入校验，并提供统一的删除确认入口。
- Prompt、解决方案、学习笔记、UI 原型、分类、标签和批注的现有删除调用需要接入输入确认。
- 解决方案、学习笔记和 Prompt 等删除文案需要与当前数据库级联行为保持一致。
- 后端 Controller、Service、Prisma Schema 和 DELETE API 不需要变更。
- 不引入新的 UI 框架或第三方依赖，继续复用本地 `Input`、`Button` 和 Tailwind CSS。
