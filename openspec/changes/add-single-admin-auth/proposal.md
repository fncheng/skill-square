## Why

当前项目没有认证与授权边界，任何能够访问页面或直接调用 API 的人都可以新增、编辑、导入、收藏、回滚或删除内容。项目需要一个与现有单人维护模式匹配的轻量登录系统，让公开访问者保持可浏览、可复制和可导出，同时把所有数据写操作收敛到唯一的 `admin` 管理员。

## What Changes

- 增加单管理员登录、会话查询和退出能力，不提供用户注册、用户管理或多角色体系。
- 使用服务端签发的 `HttpOnly` Cookie 保存管理员会话，前端不接触认证 Token。
- 将所有非安全 HTTP 方法默认纳入管理员授权保护；访客直接调用写接口时返回 `401 Unauthorized`。
- 前端根据会话状态显示“登录”或“Admin”入口，并保护新增、编辑、分类管理和标签管理路由。
- 访客界面隐藏或禁用新增、编辑、删除、导入、收藏、回滚以及批注写入操作，但继续允许列表、详情、搜索、版本历史、复制、导出和已有批注查看。
- 增加登录尝试频率限制、生产 Cookie 安全属性和必要的认证环境变量，且不提供不安全的默认生产密码。
- 同步 Swagger、API 文档、架构说明、环境变量示例和三套 Docker Compose 部署配置。

## Capabilities

### New Capabilities

- `single-admin-authentication`: 定义唯一管理员的凭据校验、登录、会话查询、退出、会话 Cookie 以及登录频率限制。
- `visitor-read-only-access`: 定义访客与管理员在 API、前端路由和页面操作上的只读/可写权限边界。

### Modified Capabilities

无。现有 `typed-delete-confirmation` 行为继续用于已登录管理员执行的删除操作。

## Impact

- 后端：新增 NestJS 认证模块、DTO、会话签发与校验逻辑、全局写操作 Guard、Cookie 解析、登录频率限制和 Swagger 安全描述。
- 前端：新增认证 API、Zustand 认证状态、登录页面、管理员路由保护和统一的管理员可见性控制；调整现有 Axios 认证失败处理。
- 现有业务：Prompt、解决方案、学习笔记、Markdown 批注、UI 原型、分类和标签的写接口全部进入授权范围；查询与导出接口保持公开。
- 配置与部署：增加管理员凭据哈希、会话签名密钥、会话有效期和安全 Cookie 配置，并在本地、GHCR、离线 Compose 路径中统一传递。
- 依赖：预计新增 JWT、Cookie 解析、密码哈希和请求限流相关的后端依赖，不新增数据库用户表或认证迁移。
